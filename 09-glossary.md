# 9. Glossary

Plain-language definitions, alphabetized. Each links back to where it's explained in depth.

- **AJAX / XHR** — older names for "the frontend fetching data from the server without reloading the page." Same idea as [`fetch`](05-apis-and-fetch.md).
- **API** — the "menu" of requests the backend will answer, and the format for asking. [More →](05-apis-and-fetch.md)
- **Async / asynchronous** — "doesn't finish instantly; we wait for it." Describes fetches and anything with a delay. [More →](05-apis-and-fetch.md)
- **Backend** — the invisible server side: logic, databases, security. The kitchen. [More →](01-big-picture.md)
- **Branch** — a parallel copy of the code to work in safely; like duplicating a Figma page. [More →](08-dev-workflow.md)
- **Browser** — the program (Chrome, Safari…) that downloads and runs the frontend. The runtime. [More →](01-big-picture.md)
- **Bug** — behavior that differs from what's intended. [More →](08-dev-workflow.md)
- **Build** — turning source code into the runnable app; "the build is red" = it failed. [More →](08-dev-workflow.md)
- **CI/CD** — automation that tests and deploys on every change. [More →](08-dev-workflow.md)
- **Client** — the frontend running on one user's device. [More →](01-big-picture.md)
- **Client-side** — happens in the browser, no server trip; usually instant. [More →](01-big-picture.md)
- **Clarity (CuiX)** — Coupa's code design system; `Cui` prefix = Clarity UI component. [More →](04-design-systems-in-code.md)
- **Code Connect** — Figma feature mapping a Figma component to its code snippet. [More →](04-design-systems-in-code.md)
- **Commit** — a saved, named snapshot of code changes. [More →](08-dev-workflow.md)
- **Component** — a reusable piece of UI; = a Figma component. [More →](03-react.md)
- **CSS** — controls how things look and lay out: color, spacing, type, layout. [More →](02-building-blocks.md)
- **Deploy** — push code to an environment so it runs there. [More →](08-dev-workflow.md)
- **DevTools** — the browser's inspector; the **Network tab** shows live API calls. [More →](05-apis-and-fetch.md)
- **Endpoint** — one specific thing you can request from an API, with a URL + method. [More →](05-apis-and-fetch.md)
- **Environment** — where the app runs at a stage: local / dev / staging / production. [More →](08-dev-workflow.md)
- **Feature flag / toggle** — switch a feature on/off without deploying; enables A/B tests & gradual rollout. [More →](08-dev-workflow.md)
- **`fetch`** — the command that makes a request to the backend and waits for the response. [More →](05-apis-and-fetch.md)
- **Flexbox / Grid** — the two CSS layout systems for arranging and reflowing items. [More →](02-building-blocks.md)
- **Frontend** — the visible client side: your UI, running in the browser. The dining room. [More →](01-big-picture.md)
- **Git** — version control for code; Figma version history + branching, for code. [More →](08-dev-workflow.md)
- **GitHub** — the hosted home for Git repos and collaboration. [More →](08-dev-workflow.md)
- **GET / POST / PUT / PATCH / DELETE** — HTTP methods: GET = read, the rest = change. [More →](05-apis-and-fetch.md)
- **Hook** (React) — a packaged bit of React logic; names start with `use` (`useState`, `useEffect`). [More →](03-react.md)
- **Hotfix** — an urgent fix shipped outside the normal cycle. [More →](08-dev-workflow.md)
- **HTML** — defines structure and meaning of content (headings, buttons, lists). [More →](02-building-blocks.md)
- **HTTP** — the protocol browsers and servers use to talk; carries requests/responses + status codes. [More →](05-apis-and-fetch.md)
- **JavaScript (JS)** — makes the page behave: clicks, logic, fetching, animation. [More →](02-building-blocks.md)
- **Jira** — ticket/issue tracker for work items. [More →](08-dev-workflow.md)
- **JSON** — the labeled-text format data travels in; the raw material of your screen. [More →](05-apis-and-fetch.md)
- **Merge** — fold a finished branch back into `main`. [More →](08-dev-workflow.md)
- **Optimistic UI** — show success immediately, confirm with server after, roll back on failure. [More →](07-states-and-edge-cases.md)
- **Polling** — repeatedly asking the server "is it ready yet?"; the opposite of a webhook. [More →](06-webhooks.md)
- **Production ("prod")** — the live app real users use. Never break it. [More →](08-dev-workflow.md)
- **Props** — inputs passed into a component to configure it; = Figma variant properties/overrides. [More →](03-react.md)
- **Pull request (PR)** — a proposed code change under review; like a design critique. [More →](08-dev-workflow.md)
- **React** — the library for building frontends out of components. [More →](03-react.md)
- **Render / re-render** — React drawing or redrawing the UI (happens when state changes). [More →](03-react.md)
- **Repository ("repo")** — a project's codebase + history. [More →](08-dev-workflow.md)
- **Request / response** — the two halves of a server trip: you ask, it answers. [More →](05-apis-and-fetch.md)
- **Responsive / breakpoint** — CSS rules that change layout at screen-width thresholds. [More →](02-building-blocks.md)
- **Rollback** — revert a bad deploy to the previous version. [More →](08-dev-workflow.md)
- **Runtime** — the environment where code runs (for frontend, the browser). [More →](01-big-picture.md)
- **Server** — the central backend computer answering many clients. [More →](01-big-picture.md)
- **Server-side** — happens on the server; needed for security, secrets, trusted calculations. [More →](01-big-picture.md)
- **Skeleton** — gray placeholder shapes shown while data loads; better perceived speed than a spinner. [More →](07-states-and-edge-cases.md)
- **SPA (single-page application)** — an app that updates parts of the page without full reloads; typical React app. [More →](01-big-picture.md)
- **Sprint** — a fixed (often 2-week) work window the team commits to. [More →](08-dev-workflow.md)
- **Staging** — a production-like environment for testing and design QA. [More →](08-dev-workflow.md)
- **State** — data a component remembers and can change; drives the UI. Where UX lives. [More →](03-react.md)
- **Status code** — 3-digit result of a request: 200 OK, 404 not found, 500 server error… [More →](05-apis-and-fetch.md)
- **Token (design token)** — a named design value (`color-action-primary`) shared by Figma and code. [More →](04-design-systems-in-code.md)
- **Test** — automated check that code still behaves correctly; blocks shipping if failing. [More →](08-dev-workflow.md)
- **TypeScript (.ts/.tsx)** — JavaScript plus a type-safety layer; `.tsx` = a React component file. [More →](02-building-blocks.md)
- **`useEffect`** — React hook for "do something when the screen appears / data changes," often fetching. [More →](03-react.md)
- **`useState`** — React hook that holds a piece of state. [More →](03-react.md)
- **WebSocket / server-sent events** — a live, always-open connection pushing updates to the browser in real time. [More →](06-webhooks.md)
- **Webhook** — an automated message one system pushes to another the instant an event happens, via a pre-agreed URL. "Don't call us, we'll call you." [More →](06-webhooks.md)
